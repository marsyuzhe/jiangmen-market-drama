# 菜市场风云：今天谁先没电？

一部由你亲自决定结局的菜市场连续剧。你刚接手幸福路第一菜市场的三号蔬菜摊，本来只想卖卖菜、收收钱，结果第一天营业就演成了五集电视剧。

**菜可以不卖，电不能不剩。**

TRAE Friends 1024 代码盲盒作品 · 三个随机关键词：`电视剧` + `电量表` + `菜市场大字报风`。

---

## 一、怎么玩

打开网页 → 看片头 → 输入主演姓名 → 开始营业。

- 点击电视画面 / 空格 / 回车：逐字显示时先补全整句，再点推进下一句。
- 数字键 `1`–`5` 或直接点击：做出剧情选择。
- `Esc`：打开 / 关闭设置面板。
- 右上角「主菜单」：随时退出，进度自动保存。

单周目约 3–6 分钟，8–9 次关键选择，5 集、38 个剧情节点、5 个结局。精神电量会真实影响可选项、角色反应、台词与结局。

### 精神电量

初始 100%，只能在 0–100% 之间变化，不会变成负数，也不会因为归零卡死。

| 电量 | 状态 | 表现 |
| --- | --- | --- |
| 76–100% | 精神饱满 | 绿色电池，思路清楚 |
| 41–75% | 勉强营业 | 黄色电池，开始省电式吐槽 |
| 16–40% | 精神告急 | 橙色电池，解锁摆烂类选项 |
| 0–15% | 即将关机 | 红色电池，解锁收摊 / 提前关机分支 |

### 五个结局

| 结局 | 名称 | 大致触发条件 |
| --- | --- | --- |
| A | 菜市场精神领袖 | 停电时帮助过摊主，人缘 ≥ 2，最终电量 ≥ 35% |
| B | 幸福路第一顶流 | 走红路线，且最终电量 ≥ 25% |
| C | 原地关机 | 电量 ≤ 15%，或主动提前收摊 |
| D | 菜市场宇宙（隐藏） | 对神秘人保持好奇并送出那根葱，第五集回头 |
| E | 普通的一天 | 不追热点、不逞强，平稳收摊 |

结局判定看的是整局累计的剧情标记与最终电量，不是最后一次点击。

## 二、三个关键词怎么融进去

**电视剧**：不是套一层皮，而是整个产品的叙事结构。片头「幸福路电视台」、每集片头卡、字幕框逐字对白、放大特写、录像带故障、大字报砸入、「未完待续」与片尾滚动，共同构成观看体验；五集各有标题、冲突和小悬念。

**电量表**：既是 HUD，也是核心状态机。电量档位改变台词与可选项（如低电量解锁「坐下」「收摊」），并参与结局判定；剧情里菜市场停电与现实中的精神电量互相呼应。

**菜市场大字报风**：米黄旧纸、套色偏移、手写价格牌、红黄促销色、胶带与印章、颗粒与扫描线；选项、状态、结局海报全部沿用同一套大字报视觉语言，而不是常规 SaaS 卡片。

## 三、技术架构

纯前端，无后端、无登录、无付费 API、无实时 AI 调用。

```text
market-drama/
├── index.html
├── scripts/validate.mjs        # 剧情完整性 / 可达性校验
├── src/
│   ├── engine/                 # 纯函数游戏引擎
│   │   ├── types.ts            # 剧情、状态、结局类型
│   │   ├── storyEngine.ts      # 选项过滤、电量结算、场景推进
│   │   ├── gameState.ts        # 初始状态、电量分档、边界限制
│   │   ├── endingResolver.ts   # 结局与标签判定
│   │   └── saveManager.ts      # localStorage 版本化存档
│   ├── story/                  # 数据驱动剧情
│   │   ├── scenes.ts           # 38 个剧情节点 / 30 个选项
│   │   ├── episodes.ts         # 5 集元数据
│   │   ├── endings.ts          # 5 个结局定义
│   │   └── characters.ts       # 角色与称呼
│   ├── components/             # 电池表、对白、选项、角色、场景、舞台、转场、设置
│   ├── screens/                # 片头/主菜单、游戏、结局、图鉴
│   ├── services/               # Canvas 海报生成、Web Audio 音效
│   └── styles/                 # tokens / global / stage / game / screens
```

- React 18 + TypeScript（strict）+ Vite 5，原生 CSS，无 UI 框架。
- 剧情完全数据化：新增节点只需往 `scenes.ts` 加数据，不改组件；跳转由 `next` / `nextSceneId` 声明。
- 角色与场景均为原创内联 SVG：6 个角色 × 8 种表情、8 个场景背景（清晨菜市场 / 玩家摊位 / 直播摊位 / 人群围观 / 停电 / 恢复照明 / 片场 / 媒体采访）。
- 存档键：`caimao.save.v1`、`caimao.settings.v1`、`caimao.gallery.v1`、`caimao.playerName`；读取时校验版本、节点存在性与电量范围。
- 海报：Canvas 2D 绘制 1080×1920 PNG，`canvas.toBlob` + 下载链接，中文字体回退到系统黑体/苹方。
- 音效：Web Audio API 实时合成，默认静音，首次用户交互后才初始化。

## 四、运行

```bash
npm install
npm run dev        # 默认 http://localhost:5173
```

开发服务器如端口被占用，可指定端口：`npm run dev -- --port 4318 --strictPort`。

### 构建与预览

```bash
npm run build      # tsc --noEmit && vite build，输出 dist/
npm run preview    # 预览生产构建
```

`vite.config.ts` 中 `base: './'`，`dist/` 可直接部署到任意静态目录或活动大屏机器。

### 校验与检查

```bash
npm run check      # TypeScript 类型检查
npm run validate   # 剧情完整性校验（见下）
```

`npm run validate` 会模拟全部可选路径，检查：跳转目标是否存在、是否有不可达节点 / 无选项死路、电量是否越界、五个结局是否都能在真实路径中抵达、单周目选择次数是否在 8–12 次。

## 五、额外功能

- **结局海报**：结局页可下载 1080×1920 PNG，配色随结局变化；同时提供 CSS 预览与「复制结局文案」。
- **结局图鉴**：已解锁显示标题/奖项/台词，未解锁显示剪影与线索提示，不剧透。
- **设置**：音效开关、减少动画、现场演示模式、菜市场环境音；`Esc` 可随时呼出。
- **现场演示模式**：选项放大、数字键抢答、减少辅助说明，适合投影；观众喊数字，演示者按键。
- **断点续玩**：每次推进或选择都会写入 localStorage，刷新后主菜单出现「继续上次的营业」。

## 六、已知问题与边界

- 音效由 Web Audio 合成，必须经过一次用户交互（开始营业 / 打开音效）才会出声；这是浏览器自动播放限制，不是故障。
- 海报使用系统中文字体（微软雅黑 / 苹方 / 思源黑体回退），不同操作系统下字形略有差异；已在 Edge 中验证中文无乱码、无截断。
- 现场演示模式主要改变选项尺寸与键盘操作，未实现观众端实时投票（按需求不需要服务器）。
- 移动端为上下布局，选项位于电池表下方，屏幕较矮时需要轻微滚动才能看到全部选项。
- 主菜单上的「38 个剧情节点」为当前版本统计，若继续扩写剧情需同步更新文案。
- 项目按 1024 活动场景优化了桌面与手机，未针对超宽 4K 投影做专门缩放；浏览器缩放即可适配。
- 未做多语言，界面与剧情均为简体中文。
